# development の使い方ガイド

AI エージェントが `docs/development/` を運用する際の手順と、リポジトリ指示（AGENTS で示される最重要ルール）のサンプルをまとめています。ガイド類のハブは必ず `docs/guide/README.md` を参照してください。

## 最重要指示の抜粋

- 回答・ドキュメントは日本語で記載すること（中国語表現は禁止）。
- ひらがなのみ・カタカナのみでの表現は避ける。
- 必ず `docs/guide/README.md` を起点にガイドを確認する。
- main への直接コミット／push は特別な許可がない限り禁止。
- 「GO（go を含む）」は計画承認の合図。不明瞭なら再確認する。

## `docs/development/` 配下の使い分け

- `memo/`: 調査メモや簡易な記録。トピック名を日本語・英語のペアで付ける（例: `2025-10-01_0912_障害調査_MemoInvestigation.md`）。  
- `operation/`: 実行ログ。実行計画名を日本語・英語のペアで付け、コマンドと結果を Markdown で残す（例: `2025-10-01_0912_実行計画移行状況確認_ExecutionPlanMigrationStatus.md`）。  
- `task/`: 実行計画のレビュー用。計画名を日本語・英語のペアで記録し、承認後に実行する。

### ファイル名ルール（共通）

```
<YYYY-MM-DD_HHMM>_<名称(日本語)>_<サフィックス>.md
```

- サフィックスは区別が必要なときに付与（不要なら省略できる）。
- 英語名バージョンを併せて作る場合は `<名称(英語)>` に置き換える。

## 実行計画と実行ログの流れ

1. **計画立案**: 計画名を日本語・英語で決め、「実行計画 <日本語> <英語>」の形式で共有。
2. **レビュー**: `docs/development/task/` に計画を残し、承認（GO/OK 等）を得る。
3. **実行**: 計画に従ってコマンドを実行。結果は 20 件程度まで要約をつける。
4. **記録**: 実行ログを `docs/development/operation/` に Markdown で保存。コマンドと結果を必ず含める。
5. **評価**: コード変更があればテスト実行またはコードレビュー結果を記載。ドキュメントのみの場合は整合性レビューを記す。

## 記録時のチェックリスト

- 文字コードは UTF-8、改行は LF。
- 一時ファイルを作る場合は `storage/tmp/` のみを使用（ソース管理外）。
- 既存の命名・配置ルール（`docs/README.md` や AGENTS 指示）を優先。
- 変更後は「変更ファイル一覧」を必ず示す（AGENTS の重要指示）。
